## 슬라이드가 말하는 것 (4교시 실습)

- **문제:** 4×4 격자, 행·열·대각선 합이 같음(예: **합=34**). 1~16 중 **빈 칸 2개** 위치를 찾고 빠진 수를 채움.
- **예시:** (2,4), (3,3)이 `?` — 손으로는 “어느 줄 합이 34인지 / 남은 수가 뭔지”를 맞추는 작업.
- **설계(ECB):**
  - **Entity:** `MagicSquare`, `Cell`, `SolveResult`
  - **Control:** `SquareValidator`, `MissingFinder`, `Solver`
  - **Boundary:** `GridUI`, `InputHandler`, `ResultDisplay`
- **실습 목표:** ECB 분류 완료 + **문제인식/실패 조건 3가지 이상** 도출.

페르소나(4×4 **부분** 마방진을 손·코드로 다루는 **학습자**)와 잘 맞습니다. 다만 이건 **과제 설계서**이지, Mom Test **인터뷰 답변**은 아닙니다.

## Mom Test 워크북과의 관계

| 슬라이드 | Mom Test |
|----------|----------|
| ECB, Solver, Validator | 솔루션·설계 (인터뷰에서 “그건 나중”) |
| “빈 칸 2개 채우기” | 행동 **주제**일 뿐, 과거 사실 아님 |
| 실패 조건 3개 | **설계용** 실패 조건 ≠ **사용자 불편** 증거 |

이전에 요청하신 **1. 표면 문제 / 2. 진짜 문제 / 3. 증거 3줄**은, 슬라이드만으로는 **인용할 답이 없어** 여전히 작성할 수 없습니다.  
(예: “지난주 수요일, 종이로 40분 하다가 줄 합이 안 맞아서 포기” 같은 **당신의 과거 한 줄**이 필요합니다.)

## 슬라이드 실습 목표 쪽 (참고 — Mom Test 아님)

**문제인식/실패 조건** 예시(설계 관점, 인터뷰 증거 아님):

1. 빈 칸이 0개 또는 3개 이상 → 부분 마방진 전제 위반  
2. 이미 들어간 수가 1~16 밖이거나 중복 → 입력/상태 오류  
3. 어떤 행·열·대각선도 목표 합(34)에 도달 불가 → **판정 불가** 또는 무해  
4. 빈 칸 위치는 찾았는데 남은 수 후보가 2개 이상 → **유일하지 않음**  
5. 손 계산과 코드 결과 불일치 → **재현·검증** 실패

이건 ECB의 `SquareValidator` / `MissingFinder` / `Solver` 경계를 잡는 데 쓰기 좋습니다.

## 1) 주제 한 문장 (Mom Test 기반, 솔루션 최소화)

> **4×4 부분 마방진(빈 칸 2, 합 34)을 채운 뒤, 틀린 행·열·대각선을 빠르게 짚어 주는 판정**으로 학습자의 반복 계산과 확신 없는 중단을 줄인다.

## 2) R-G-I-O

| | 내용 |
|---|------|
| **Role** | 4×4 격자, 빈 칸 2개(`0`), 1~16, 합 34를 맞추는 **학습자** (손 풀이 → 코드/과제로 옮김) |
| **Goal** | 빈 칸을 채운 상태에서 **합 34·중복·범위**를 스스로 확신할 수 있게 하고, **어느 줄이 깨졌는지** 알 수 있다 |

| **Output** | **통과/실패** + 실패 시 **깨진 행·열·대각선 식별**(예: `row:3`, `diag:main`) — “맞는 것 같다”만 나오는 출력은 Goal 미달 |
